Answering "why aren't all folders on GitHub":

Nothing is missing by accident — there are ZERO untracked files.
What's excluded is excluded on purpose:

  venv/                    ~hundreds of MB of installed packages.
                           Rebuilt with: pip install -r requirements.txt
  frontend/node_modules/   Same idea. Rebuilt with: npm install
  __pycache__/, *.pyc      Compiled bytecode, regenerated on every run
  logs/                    Runtime logs
  .env                     YOUR API KEYS — must never be published
  memory/aura_memory.db    Your conversation history
  memory/*.json            Mistake log, relationship state
  frontend/dist/           Build output, regenerated by npm run build

Publishing venv/ and node_modules/ would add gigabytes, break on any other
machine (they contain OS-specific binaries), and is why every Python and
Node project ignores them. Anyone cloning your repo runs two install
commands and gets a working copy.

Two things left for you to decide (I did NOT touch either):

1. 33 files show as "modified" but have ZERO real changes — your working
   copy is CRLF, git stored LF. Committing them would create a ~257-line
   churn commit touching LICENSE, README and config files you never
   edited, and would wreck git blame on them.
   Proper fix if you want it, as its own commit:
       echo "* text=auto eol=lf" > .gitattributes
       git add --renormalize .
       git commit -m "Normalise line endings to LF"

2. frontend/memory/relationship_state.json and observation_memory.json are
   tracked and public — AURA's trust score, mood, and screen observations.
   You chose to leave them. To remove later without deleting them locally:
       git rm --cached frontend/memory/*.json
       echo "frontend/memory/*.json" >> .gitignore
