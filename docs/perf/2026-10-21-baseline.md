## What this shows (written by hand after the run)

1. **Home and Aura Domain are GPU-bound at 5–6 fps.** The GPU (Iris Xe) is 78–99% busy, while the window's own code uses ~1.3% of the machine's CPU (about 15% of one core). Frames are waiting on the GPU, not the CPU.
2. **The cost follows the black hole's draw loop, not what's visible.** Hiding the video, particles, black hole and cursor lens with CSS, even all four at once, never lifted Home above 6 fps or brought the GPU below ~77%. CSS hiding stops a layer being composited but not its JS loop. The black hole is the only animation loop that runs only on Home. The pages, which run the same video, particles and cursor lens without it, hold 48–57 fps at ~30% GPU. Its canvas is sized to the window's *diagonal*: 2175×2175 px here (4.7 MP, 2.4× the screen's pixels). It is redrawn every frame with stacked `shadowBlur` glows, additive (`lighter`) passes and fresh gradients, and it never pauses itself. *This is an inference: stopping the loop (not hiding it) is the confirming test.*
3. **The Domain inherits it.** The Domain opens as an overlay; Home, black hole included, stays mounted and drawing underneath.
4. **Pages are fine but not perfect:** 48–57 fps, 1–6% slow frames, ~30% GPU. That is the background video, the particle field and the cursor lens.
5. **Thinking/speaking made no difference.** The GPU is already saturated when idle.
6. **Memory:** AURA uses ≈ 620–690 MB on Home and the pages, 812 MB in the Domain, 578 MB minimised. Of that, the GPU process is ≈ 400–570 MB, the brain ≈ 93 MB, the main window 74–99 MB and the buddy 17–20 MB.
7. **Minimised is cheap:** 0.3% CPU, 0.3% GPU, so drawing does stop. The buddy alone costs 0.1–0.4% CPU.
8. **The brain is light:** 0.1–0.4% CPU, ~93 MB, and listening 2.9 s after launch (11.5 s on a cold disk cache in an earlier trial).
9. **Screen OCR runs blind.** There were 153 failed OCR attempts in this ~27-minute run (≈ one every 10 s), each preceded by a full-screen screenshot, because Tesseract isn't installed. The CPU cost is small today, but the work is pointless, and it made up 153 of the run's 317 log lines.

**Noise in this run:** other apps were in use (VS Code, Comet, ChatGPT). The "buddy switched off" row coincides with a burst from svchost and VS Code (machine CPU 62%), so its 99% GPU says nothing about the buddy. The measuring script itself cost 5–7% CPU in this run, and its GPU-memory column is the peak over each window. The script has since been changed to cost ~1.3% CPU and to read GPU memory at the end of each window, so later runs are comparable on everything except those two details.
